# Builder rules (every page-builder agent follows these)

File: Synaptix — Brand System 2.0 · key xeHvJ6cogxBAE6AZHCCzJu
0. Load the Figma skill before any use_figma call: mcp__Figma__get_figma_skill "skill://figma/figma-use/SKILL.md" (+ relevant references). Load tools via ToolSearch: mcp__Figma__use_figma, mcp__Figma__get_screenshot, mcp__Figma__get_figma_skill, mcp__Figma__get_metadata.
1. Read spec/brand_spec.md, spec/figma_use_notes.md, and spec/build_log.md (ids of variables, styles, components). Work ONLY on your assigned page. Never delete nodes you did not create. Never modify variables/styles/components made by others (instances are fine).
2. Page canvas convention: one or more top-level FRAMES named "<pageNo> · <Section title>" (e.g. "01 · Research overview"), width 1600 px for documentation pages, laid out in a vertical stack with 120 px gaps starting at x=0,y=0 (application artboards keep their own real sizes, side by side with 160 px gaps). Each doc frame: white bg (bind fill to semantic/bg/canvas), padding 96, auto-layout vertical, gap 48. Every frame starts with a header row: kicker (Label/12 Mono, Ink/500), title KO (Heading/H1 48), title EN (Heading/H3 24, Ink/700).
3. Text: KO first, EN directly beneath in Ink/700 (Body/S 14 or Body/M 16). Apply TEXT STYLES by id (from build_log) — never ad-hoc font settings except where a style truly doesn't fit (then still use "IBM Plex Sans KR" / "IBM Plex Mono"). Load every font with figma.loadFontAsync before creating text. Wrapping text: textAutoResize = "HEIGHT" with layoutSizingHorizontal="FIXED"/explicit resize (FILL collapsed to 0 in this file — see notes). Max text width 720 px for body copy (two-column when the frame is 1600 wide: use a horizontal auto-layout row with two 664-px columns and 80 gap).
4. Colour: bind fills to variables (node.setBoundVariable or fills with setBoundVariableForPaint) or apply paint styles by id. No off-palette hex. Contrast: body text ≥4.5:1, large ≥3:1 (use only the pairs approved in spec §10).
5. Tables: build as auto-layout (vertical list of horizontal rows); header row Ink/100 bg, Label/12 Mono text; cells Body/S 14, cell padding 12/16, row min height 44, 1 px bottom border Ink/200 (use a stroke on the row frame, bottom only via strokeBottomWeight). Fixed column widths that add up to the table width.
6. Callouts: rounded 8, left border 4 px — finding: Brand/Cobalt 600 on Brand cobalt-100 bg; hypothesis: Functional/Warning 600 on #FFF4E5-like → use ink/100 bg with warning-600 border; limitation: Ink/500 border on Ink/50 bg. Prefix text with "발견 · Finding", "가설 · Hypothesis", "한계 · Limitation".
7. Build in chunks: one use_figma script per section (keep each script under ~250 lines), return created node ids, and re-use them. After every 2–3 sections screenshot the frame (get_screenshot, maxDimension 1600, curl to scratchpad/logs/<page>_<n>.png, then view with Read) and fix clipping, overflow, overlap, wrong fonts (hasMissingFont), zero-width texts.
8. Section frames on the page must not overlap; keep every frame's content inside its bounds (clipsContent=false so overflow is visible during QA, then fix).
9. Finish by (a) a final full-page screenshot review, (b) appending "## <page> (agent: <name>)" to spec/build_log.md with the top-level frame ids, the component ids you created, and anything unresolved, (c) a ≤10-line summary as your final message. Never paste large JSON into the final message.
